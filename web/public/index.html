Healthcare support for better diagnosis

CareBridge is a console-based hospital workflow prototype — patients find nearby hospitals, browse doctors and book appointments; doctors triage a priority queue and keep health records. It now runs in the browser too: the same C++ binary, streamed to a web terminal.

What it does

Patient

  • Register and log in with a patient ID.
  • Find nearby hospitals from predefined areas, sorted by real distance (haversine).
  • Browse doctors by hospital, specialization, fee or name.
  • Book appointment slots with an urgency level (Emergency / Urgent / Routine).
  • View or cancel appointments, read health records and notifications.

Doctor

  • See pending requests in strict priority order (emergency first, then FIFO).
  • Confirm, reject or defer requests — patients are notified instantly.
  • Open and close availability slots; review the confirmed schedule.
  • Search patients and add or update health records.
  • Recently viewed patients stack for quick back-and-forth.

Data structures under the hood

Nothing here uses std::list or std::priority_queue — every structure in src/DataStructures.h is hand-written for the coursework.

OOP: Person is abstract; Patient and Doctor inherit and override display(), serialize() and role(); containers are template classes.

How the web deployment works

The web console is a thin transport layer — it never re-implements the business logic, so the C++ sources stay the single source of truth. 

 browser                      Node server (zero deps)                C++17
┌────────────────┐  POST /api/session   ┌──────────────────────┐
│ console.html   │ ────────────────────▶│ session manager      │
│  terminal UI   │                      │  one process per tab │──┐
│                │  SSE /api/…/stream   │  own data/ directory │  │  spawn
│  type a line   │ ◀────────────────────│  idle reaper         │  │
│        │       │                      └──────────────────────┘  │
└────────┼───────┘                                                │
         └── POST /api/…/input ───────────────────────────────▶  ┌▼──────────────┐
              (line + "\n" on stdin)                            │ ./carebridge  │
                                                                │ stdin/stdout  │
                                                                └──────────────┘
  • One process per browser tab with its own sandboxed data/ directory, so visitors never share state.
  • Server-Sent Events for output (no WebSocket handshake, works behind any proxy) and plain POST for keystrokes.
  • Idle sessions are reaped (30 min by default) and every session dies with the server.

Deploy it

Local / server

make
cd web && npm start
# http://localhost:3000

Docker

docker compose up --build
# http://localhost:3000

Render / Fly.io

render.yaml   # Blueprint
fly.toml      # fly launch

Build and test run on every push via GitHub Actions (Linux, macOS, Windows), and main publishes a container image to GHCR plus the static UI to GitHub Pages. Note: GitHub Pages hosts the UI only — the console there must be pointed at a backend with console.html?api=https://your-backend-host. See DEPLOY.md for the full guide and the environment variables.
